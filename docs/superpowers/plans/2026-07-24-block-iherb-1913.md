- [x] **Step 6: Verify the live GitHub Pages feed**

Fetch `https://abitraco.github.io/imweb-naver-ep/ep.txt` and confirm two things: the
served bytes match the just-pushed commit (proves propagation, not a cached prior build),
and the first TSV field has no exact match.

The feed is ~7.2 MB. A `--max-time 2` fetch cannot complete it, and GitHub Pages needs
roughly 20-60 seconds to serve a new push, so each attempt gets a generous timeout and
the loop compares sizes rather than assuming the first successful download is current.

```bash
EP_LOCAL=/Users/chance/DEV/imweb-naver-ep/ep.txt
EXPECTED_BYTES=$(wc -c < "$EP_LOCAL" | tr -d ' ')
EP_LIVE_TMP=$(mktemp)
trap 'rm -f "$EP_LIVE_TMP"' EXIT

for attempt in {1..20}; do
  if curl -fsSL --max-time 180 \
    -o "$EP_LIVE_TMP" \
    https://abitraco.github.io/imweb-naver-ep/ep.txt
  then
    LIVE_BYTES=$(wc -c < "$EP_LIVE_TMP" | tr -d ' ')
    if [ "$LIVE_BYTES" = "$EXPECTED_BYTES" ]; then
      if awk -F '\t' \
        '$1 == "iherb-1913" { found=1 } END { exit found ? 0 : 1 }' \
        "$EP_LIVE_TMP"
      then
        echo "live feed still contains iherb-1913"
        exit 1
      fi
      echo "live feed current ($LIVE_BYTES bytes), iherb-1913 absent"
      exit 0
    fi
    echo "attempt $attempt: stale build served ($LIVE_BYTES != $EXPECTED_BYTES)"
  fi
  sleep 20
done
exit 1
```

Expected: exit 0 only after the served byte count matches the local published file **and**
its first column has no exact matching row. A stale byte count means Pages has not
propagated yet — keep waiting. Exiting 1 means propagation, publishing, or fetching has
not completed and must not be reported as done.
